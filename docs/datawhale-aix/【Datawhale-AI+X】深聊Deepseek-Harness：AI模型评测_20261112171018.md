

# Datawhale AI+X：01：深聊Deepseek Harness 概述与安装 🚀

在本节课中我们将学习 Deepseek Harness 是什么，为什么需要使用它，以及如何完成安装、启动和基础配置，让初学者能够快速跑通这个工具。

Deepseek Harness 是一个用于驾驭大模型的工程系统，它的核心目标是让大模型的输出更加稳定、可控。如果你手头已经有一个很强的模型，仍然需要使用 Harness，原因主要有两点。第一，我们需要系统给我们一个稳定的输出，避免模型运行到一半就去做别的事情，或者不给出正常反馈。第二，我们希望模型在每个节点都有一个收敛的地方，而不是每次都用不同的方式完成同一件事。简单来说，Harness 就像一个驾驭工程，把大模型像编程一样进行控制，不让它乱跑。

接下来我们看看如何安装这个工具。以下是安装方式。

![](img/0e7c73ff8d183dd06a271b60863b2157_2.png)

- 命令行安装：如果你会写代码，通常会有 Node.js 环境。可以直接使用 `npx deepseek-harness` 命令启动服务。启动后，系统会提示一个端口号，默认是 3080 端口，在浏览器中访问该端口即可进入界面。
- 桌面版安装：社区有老师制作了桌面版，Windows 对应 EXE 安装包，Mac 对应 DMG 安装包。安装过程简单，适合不会操作命令行的用户。但需要注意，桌面版暂时没有适配插件功能，只能用来尝鲜，长期使用仍建议用命令行启动。

![](img/0e7c73ff8d183dd06a271b60863b2157_8.png)

安装完成后，进入界面需要进行基础配置。以下是配置步骤。

![](img/0e7c73ff8d183dd06a271b60863b2157_10.png)

- 获取 API Key：访问 Deepseek 官网的开发平台，找到 API 开放平台，创建一个 API Key，给它起个名字，然后复制这个 Key。
- 填入配置：在 Harness 界面中，将复制的 API Key 填入相应位置。
- 新建工作区：配置完成后，先不要着急，新建一个工作区，比如命名为 ground，然后将工作区加入进来，之后就可以在这个工作区里进行操作。

启动成功后，你会看到一个日志模块，记录每次交互生成的历史对话。这些历史对话可以下载下来，方便溯源和排查问题，对设计产品来说会更好一些。

上一节我们介绍了 Deepseek Harness 的核心特性与预设模式，本节中我们来看看它的系统架构、核心主线以及消息生命周期。

![](img/0e7c73ff8d183dd06a271b60863b2157_92.png)

Deepseek Harness 的架构有三条设计主线，共同支撑起整个框架。

第一条主线是 composition，即能力如何装配成产品。它介绍了一些能力组件，告诉我们如何把不同的能力组合在一起。

第二条主线是 session，也就是我们之前看到的日志模块和轨迹记录。这是 Harness 的核心之一，记录了每一步的执行轨迹。

第三条主线是执行线。执行线不仅包括当前正在执行的工具，后台还会开启 agent 并运行一些并行工具，帮助完成执行任务。

这三条主线共同构成了 Harness 的整体框架，而最核心的部分就是插件模块。

接下来我们看看系统边界。以下是系统的组成部分。

- 外部端：web house，因为 Harness 是由服务器执行的，所以系统部署在外部端。
- 中间层：agent 和 proide 提供方，与外部端进行通信。
- 核心层：使用 ent，包括 route、prompt、time 执行、日志等。
- 外部依赖：上下文、工具、大模型以及其他组件。

从代码层面来看，Harness 的核心是 server，所有内容都被放入 package 中。API、大模型、sandbox、skill 等能力都被做成了组件，通过 codeice service 服务串联起来。这是一个非常扁平的架构，我们可以直接通过 API 和 route 来管理组件，构建出一套可用的系统。

在运行机制上，Harness 有预设的启动机制和停止机制。为了节约上下文，每次加载某个工具时，会把对应的上下文切贴过来，保证每个工具使用起来是模块化的，不会长篇大论地引用无关内容。

消息的生命周期也很简单。以下是基本流程。

- 用户发送一条消息。
- 系统生成一条 log。
- 提示词被组合起来。
- 大模型根据提示词生成内容。
- 大模型调用工具。
- 工具执行完成后，判断是否结束。

整体来看，这是一个非常简单且扁平的框架，方便大家理解和学习。

# Datawhale AI+X：04：Deepseek Harness 插件开发与市场分享 📦

上一节我们深入讲解了 Deepseek Harness 的系统架构与运行机制，本节中我们来看看如何开发一个插件，并将其分享出去。

在 Deepseek Harness 中，开发插件的核心非常简单，只需要一个 TS 模块文件，通常是 index.ts。每个插件需要保持一个明确的声明，并且在核心模块中被加载进来。也就是说，我们需要对整个系统来说，有新插件就要告诉它，把它放进来，而不是随便写一个插件它就能识别。

以下是插件的基本代码结构。

```ts
// index.ts 插件入口文件
import { CTX } from 'dsh-core'

export function register(ctx: CTX) {
  // 注册插件逻辑
  ctx.registerPlugin({
    name: 'image-generator',
    type: 'tool',
    // 其他参数
  })
}
```

写好插件后，需要将其导入到系统中。每次启动时，会有一条日志显示注册成功，例如出现特定标记，就说明插件已经被加载进来。你也可以在网页端客户端的插件列表里，输入关键字查看该插件是否已启动和加载。

举个例子，开发者可以开发一个图片生成插件（image generator），调用 Q3.0 或 dream5.0 等模型。开发完成后，可以让大模型直接帮助加载插件，或者使用 Z code 等工具加载。如果启动时出现冲突，可以更换 cloud code 等其他工具进行加载。

插件开发完成后，可以将其分享到社区。以下是分享方式。

- 将项目上传到 GitHub。
- 在项目中添加 topic 标签 `dsh-gang`，这样其他人就能搜索到你的插件。
- 目前插件市场已经有一千多个插件，数量还在快速增长。

需要注意的是，安装插件前建议先扫描安全漏洞，避免安装带有病毒或恶意代码的插件。社区中也有一些有趣的 UI 插件，比如 open design，可以用来做界面或 PPT，TS 框架让 UI 修改相对简单。

本节课我们一起学习了如何编写 index.ts 插件入口、如何使用 CTX 类注册插件、如何验证插件是否加载成功，以及如何将插件分享到 GitHub 插件市场。下一节我们将介绍企业个性化与二次开发的方法。

# Datawhale AI+X：07：Deepseek Harness 常见问题与 Q&A 🔍

上一节我们分享了 Deepseek Harness 的实战案例与经验，本节中我们来看看使用过程中常见的问题及其解决方法。

以下是整理的常见问题。

- Node.js 版本：新版本（如 26.04）使用 npx 安装可能会报错，建议使用 LTS 版本，例如 24，更稳定。Windows 用户可以下载 npm 的历史版本或 LTS 版本进行降级。
- macOS 环境：macOS 滚动更新到最新版后，使用 npx 方法运行通常没有问题。
- 包冲突：如果出现包封住或全局安装重复包的情况，需要回去排查 npm 全局包。
- Windows 终端：Windows 上的 CMD 优化不够好，建议在 WSL 或 Linux 环境下运行，不要在 Windows 原生命令行里写代码。
- PTC 模式变量隔离：PTC 模式每次单独创建环境，变量默认不会从上一个运行时继承到下一个。如果需要共享信息，可以写一个 memory 文档，让模型直接读取物理存储，或者使用外部 memory 工具。
- 搜索 Bug：搜索 huggingface 链接等操作时可能会出现一直报错或死循环，可能是 TypeScript 内存错误，新建一个任务通常可以解决。如果问题持续，可以去官方留言并放上截图反馈。
- 模型适配：Harness 可能更适配 GPT 5.5 或 5.6 这类模型，但如果没有相应 API，可以先使用已有的 plan。
- 插件列表：目前插件列表比较简陋，没有详细分类和使用说明，readme 文档在源码的 package 目录下。
- 翻译能力：Deepseek 的翻译能力一般，英翻中可能好一点，中翻音 GPT 可能更好，但 Deepseek 输出速度最快。
- 架构调整：Deepseek 的架构调整可能导致幻觉或上下文问题，需要理性看待，不能直接上生产环境。
- 第三方模型：使用 minm 等第三方模型效果也不错。
- 5.3 模型：5.3 是一个挺好用的东西，但价格较高，老会员费用相对可接受。
- Agent 导师：可以通过文档形式来约束 Agent，让它布置任务并逐步实现，起到导师般的指导作用，但需要注意代码风格和 UI 差异。
- 安全风险：存在 B 助 B 攻击注入等风险，模型上下文被污染时可能会出现 rm -rf 等危险操作，建议在独立环境中运行，官方目前没有自动审批机制。
- 和小龙虾的区别：小龙虾挂载网关并有心跳机制，Harness 没有网关能力，运行逻辑也不太一样。
- 前端体验：Harness 的前端网页已经有所改善，部分风格类似 Codex。
- 仓库权限：建议为 AI 单独创建一个账号作为 contributor，规避权限风险，避免直接给出系统密码。
- O4.8 之后：从 O4.8 之后，模型基本不会再出现傻傻删除系统、宕机或搞破坏的行为，约束已经比较好了。
- 缓存价格：前期缓存低价格高，后期缓存高了价格就会好起来。
