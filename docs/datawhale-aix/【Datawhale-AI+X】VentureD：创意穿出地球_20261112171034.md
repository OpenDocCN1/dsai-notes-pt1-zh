
# VentureD：创意穿出地球：01：从硅谷创业生态到 Agent 实践 🚀

👋 课程概述：在本节教程中，我们将学习 VentureD 黑客松的创办背景、核心理念，以及 Agent 在真实世界中的应用价值。内容包括从硅谷创业生态中提取的方法论，Agent 与普通聊天机器人的本质区别，大模型公司内化通用能力后应用层依然存在的机会，以及非技术背景同学如何参与 AI 创作。无论你是否具备编程基础，都能从中获得从“想法”到“Demo”的行动指南。

🔹 一、讲师背景与硅谷创业经历

上一部分我们介绍了课程概述。本节中我们来看看分享者的经历，这些经历构成了 VentureD 的核心观点。

讲师本科在 UC Berkeley 就读，后来在金山从事网络安全风险监管咨询工作，再后来去了麻省理工学院，参与组织过很多创业社群和创新活动。他在硅谷一共待了大约 7 年时间。

刚到美国时，他认为硅谷最厉害的地方是技术，那里有顶尖大学、实验室和工程师，也有非常活跃的风险投资，还有各种改变世界的科技公司。大家谈论的内容都是人工智能、自动驾驶、软件和下一代平台。

但在硅谷待的时间越长，他越觉得硅谷真正厉害的地方，不只是拥有一套敢于让普通人开始的系统。在那里，你会看到很多根本没有准备好的人已经开始行动。

一个学生发现学校里的一个小问题，就会拉着两位同学一起做项目。一个研究人员可能只有一个不成熟的技术想法，就开始寻找商业伙伴。一个人可能没有完整的团队，没有融资，甚至还没有想清楚商业模式，但是他会先做出一个 Demo，拿给身边的人看。

95% 的项目可能会失败。最后有些产品根本没有人使用，有些团队很快就会解散。但是有些人可能做了几个月之后，发现原先的判断完全错误，又换了一个新方向，最后取得成功。在这个环境里，失败并不意味着这件事情没有价值，因为你至少完成了一次从想法到现实的转换。

你不再只是说“我觉得这里可能有一个机会”，而是真的拿出了一个东西，对别人说：“这是我对这个机会的理解，你来试一下。”这两句话之间，差的就是一个东西，叫 Demo，也就是一个小的 MVP。

实际上，Demo 对应的是两种不同的身份。第一种身份是观察者，第二种身份是创造者，也就是 Builder。所以很多人和创业者之间，并不存在一道绝对的能力鸿沟。真正做得很好的创业者，智商或情商不一定比你更高。真正的区别，往往是一个人有没有获得开始的许可。

也就是说，有没有一个环境告诉你，你的想法不需要一开始就变得很成熟，你不需要先完成所有的课程，你也不需要拥有 10 年的工作经验。硅谷的一些公司，比如 Any Scale，其实就是做数据标注这件事情。它的创始团队是 MIT 的两位本科生，后来成长为一家估值几十亿甚至上百亿美元的公司。这说明你并不需要很强的工作经验或能力，才能做一些事情，你可以先做一些东西，然后拿出来让真实世界给你反馈。

这是他在硅谷期间，觉得感受最深的一件事情。所以他认为硅谷最重要的产品，其实不是它的公司，而是一整套创业生态和体系。

🔹 二、为什么我们要创办 VentureD

刚才我们介绍了讲师的硅谷经历。本节中我们来看看 VentureD 的创办初衷。

VentureD 并不是为了凑热闹而举办的又一场比赛。市面上已经有很多黑客松、论坛和创业活动，但我们观察到一个具体的问题：今天的年轻人离技术越来越近，却离“真正创造一个东西”越来越远。

每天都会刷到大量 AI 新闻、新模型、新产品、新融资消息，信息像炸弹一样轰炸我们。很多人因此变成了专业的“科技观众”，知道哪些热点好不好，也能快速评价产品好不好，但当你问他们最近是否真正做出过一个东西，他们可能会回答：“我还没有准备好”“我不是计算机专业的”“我的想法好像还不够成熟”“我不知道该从哪里开始”。

以下是造成这种现象的几个常见原因：

- 觉得自己还没有准备好
- 认为自己不是计算机专业
- 担心想法不够成熟
- 不知道从哪里开始

在 AI 时代，创造的门槛正在快速下降。以前做一个产品，可能需要一个完整的工程团队。今天，借助 AI，一个人甚至一台电脑就可以完整完成产品设计、代码生成、内容制作、数据分析和测试。但这并不意味着创造变得毫无难度。技术门槛下降之后，有一些能力反而变得更加重要，比如你能不能发现一个真实的问题，能不能把一个模糊的想法说清楚，能不能判断 AI 生成的东西对不对，能不能在时间和资源有限的情况下，把最关键的体验做出来。

我们真正想做的不是增加一场比赛，而是创造一个场域，对所有同龄人和年轻人说：你不需要等到毕业才能创业，你不需要等到拥有完整完美的团队，你不需要自己变成专业程序员，你现在就可以开始。

这也是为什么这个活动叫做 VentureD。很多人看到这个名字会问，Venture 理解了，那 D 是什么意思。我们从一开始并没有想给第一个完整唯一的标准答案。因为对于一个人来说，从一个想法到真正创造出一个东西，中间会经历很多个阶段。

第一个阶段叫 Dream。很多事情一开始都是一个模糊的念头，你可能会觉得某个问题很有趣，觉得一个产品应该存在，或者隐约感觉这件事情可以用不同的方式去完成。在这个阶段，你甚至不确定自己的想法是否正确，但所有的创造都从一个未被证实的想法开始。

第二个阶段叫 Dare，也就是勇气。你要敢于承认自己真的想做这件事情，敢于在完全没有准备好的时候开始。很多想法不是因为能力不足，而是永远停留在脑海中。所谓的勇气并不意味着你确信自己一定会成功，它意味着你即使不知道结果，也愿意迈出第一步。

第三个阶段叫 Do，就是真正动手。你会发现原先的想法可能没有那么完整，技术可能实现不了，或者用户根本不需要。只有进入这个阶段，这些问题才会真正出现。而这些问题出现的时候，不意味着失败，它意味着你的想法和现实终于产生关系了。

第四个阶段叫 Demo。我们非常强调 Demo，因为 Demo 是一个低成本测试想法的方式，它是一个完整可以体验和评价的东西。它可以很粗糙，也可以只成功运行一次，但是从它展示出来的那一刻开始，你的想法就不再是一个想法，它已经是一个产品。

VentureD 代表的是一种路径，也就是从 Dream 到 Dare，再到 Do，最后到 Demo，就是从一个想法到敢于迈出第一步，从真正动手到把它交给真实的世界。

但是 D 还有一层更重要的意义。在数学里，D 开头的一个词叫 Delta，意味着变化，代表一个状态与另一个状态之间的差值。作为一个数学系出身的人，他认为 VentureD 真正关心的正是这个变化。我们不关心你的产品做出来多复杂，也不关心你是否获得奖项，更关心的是你在准备 VentureD 之前和离开 VentureD 之后，有没有发生一点变化。这个 Delta 可能很小，但是很多人的第一家公司、第一个产品、第一个合伙人，都是从这个很小的 Delta 开始的。

D 不是一个固定的答案，它可以是 Dream，可以是 Dare，可以是 Do，可以是 Demo，它最终代表的是发生变化的自己。

还有一个 D 是 Democratic，也就是让创造变得更加普及。AI 让他感到兴奋的，并不是 AI 越变越强，而是让过去只有少数专业团队能完成的事情，开始向普通人开放，这是一个科技平权的时代。你不懂编程，也可以做产品。你学医学的、机械的、商业的，也可以成为 AI 时代的创造者。技术不应该成为少数人的特权。

🔹 三、Demo 比想法更重要：从观察者到 Builder

前面我们介绍了 VentureD 的名字含义。本节中我们来看看，什么才是进入创业的关键一步。

很多人和创业者之间，并不存在绝对的能力鸿沟。真正的区别，往往不在于智商或情商，而在于“有没有获得开始的许可”。硅谷的一个核心体验是：很多根本没有准备好的人，已经开始行动了。

这里有一个核心公式：

```text
想法 + 行动 = Demo
Demo = 最小可行产品（MVP）
```

有了 Demo，你的身份就从观察者变成了创造者，也就是 Builder。所以 Demo 比单纯的想法更重要，它是连接想象与现实的桥梁。

🔹 四、一个好的创业生态应当提供什么

刚才我们讲了 Demo 的作用。本节中我们来看看，外部环境对个人行动有多大影响。

硅谷最重要的产品，可能不是 Google 或 Meta 这样的公司，而是一整套创业生态和体系。大家常把硅谷理解为一群聪明人创造了很多伟大公司，但实际上，硅谷最重要的产品是一整套创业生态。这套体系的核心，在于大学、实验室、创业者、工程师、投资人、大公司、校园网络和各种社区之间，存在非常平等的链接。

这些链接带来了一种重要的流动性：想法能够找到技术，技术很快就能落地到场景，年轻人也能很快找到愿意帮助的人。这也是创业非常重要的一点。

我们认为，一个好的创业生态，至少应当提供以下三样东西：

1. 行政的许可：告诉你，你的想法不需要一开始就很成熟，不需要先完成所有课程，也不需要拥有十年工作经验。
2. 快速的反馈：让你把想法做成 Demo，拿给真实世界测试，得到真实反馈。
3. 人与人之间的链接：让想法、技术和用户之间，距离足够短。

当从想法到团队的距离很短，从技术到用户的距离也很短时，一个人就不会觉得创业是几年后的事情，而会觉得“这周我就可以去尝试一下”。

🔹 五、从学校到企业：技术与社会的差距

前面我们讲了创业生态的三个要素。本节中我们来看看，为什么进入企业之后，视角会发生变化。

在学校和创业社区里，我们很容易相信一件事情：只要我的技术足够先进，我的产品就一定会被使用。但是真正进入企业之后，你会发现现实世界远比一个 Demo 复杂得多。

一个企业可能会问：这个系统安全吗？它会接触哪些数据？出了错误，哪些人来负责？它是否符合监管要求？员工愿不愿意改变原先的工作逻辑和习惯？管理者是否真的信任它？你能不能和企业已经用了一年的系统对接起来？

这些问题可能没有模型参数那么“性感”，也不会出现在产品发布会最显眼的位置，但是它们决定了一项技术能不能进入真实世界。技术能够做什么，和社会愿意让技术做什么，是两件完全不同的事情。

一个实验室里的模型可以在测试中表现得非常聪明，但当它真正开始处理用户数据、控制真实设备、影响真实决策的时候，我们面对的不再只是技术问题，而是信任、责任、制度、流程和人的情绪。

这段经历影响到了 VentureD 的主题。我们的主题并不是让大家去做一个很强大的 Agent，我们的主题是 Agent for the Real World，就是让 Agent 进入真实的世界。因为对于我们来说，真正有价值的智能，不是只在屏幕里面回答一个问题。他要真实理解场景，要调用真实的工具，面对真实的限制，并对真实的人产生影响。

🔹 六、Agent for the Real World：Agent 与聊天机器人的区别

前面我们分析了从学校到企业的视角差异。本节中我们来看看，VentureD 为什么把主题定义为“Agent for the Real World”。

我们并不是因为 Agent 是一个热门概念才选择它，而是关注人工智能正在发生一个根本的变化。过去的 AI 主要负责回答问题，而现在的 AI 开始尝试执行任务。回答问题和执行任务之间，通常存在一个非常重要的分界线。

比如说，聊天机器人可以告诉你如何规划一次旅行，但是一个 Agent 可以理解你的时间、预算和偏好，寻找方案、比较方案，最后完成落实你的安排。这就是 Agent 和聊天机器人本质上的不同。

Agent 的最简单理解可以用下面的公式表示：

```text
Agent = 大模型提供的智能 + 产生行动的能力
```

VentureD 希望大家思考的，不是模型能说什么，而是模型真正能替代一个真实的人完成什么。

🔹 七、大模型公司会内化 Agent 吗？应用层还有机会吗

刚才我们定义了 Agent。本节中我们来看看，大家最关心的一个现实问题：如果 OpenAI、Anthropic、Google 等基础模型公司，把 Agent 的能力全部做进自己的产品，那么我们现在做的 Agent 还有意义吗？

答案是会内化，但这不是一件坏事。大量的通用型 Agent 能力，未来一定会被基础模型公司吸收。今天需要开发者自己完成的浏览器操作、文件读取、记忆管理、工具调用和任务规划，未来很可能都会变成模型平台的基础能力。很多今天看起来像独立产品的东西，未来可能只是一个标准功能。

如果一个项目的全部价值，只是把一个大模型接到网页上面，或者让大模型自动执行几个非常通用的步骤，那么这样的产品确实很容易被平台替代。但是，我们要区分两件事：一种技术能力被平台化，不等于这个领域没有未来。很多时候，这意味着一个更大的应用时代才刚刚开始。

比如说云计算出现之后，企业虽然不用自己购买或维护所有服务器，但更多的 SaaS 公司出现了。智能手机出现之后，虽然把摄像头、定位、支付、传感器、网络链接都内化到了手机里面，但却创造了一个无法想象的应用生态。浏览器也没有消灭所有的网站和互联网公司。基础设施解决的是共性问题，而真正的应用解决的是具体问题。

今天的大模型公司，做的 Agent 更多偏向基础设施层，会提供越来越强大的大脑。但是一个大脑并不代表一个完整的产品。一个真正能进入现实世界的大脑，还需要知道自己为谁服务，理解某个组织的具体工作流程，获得正确的数据和权限，连接特定的设备和系统，也需要知道什么事情可以做，什么事情不能做。

以下是应用层依然存在的几个核心理由：

1. 真实的场景：模型可以拥有非常广泛的知识，但它可能不知道某个具体工厂今天的生产计划发生了哪些变化，也不知道某个具体医院真实的工作流程。这些场景不会自动出现在模型里面，它需要有人进入现场观察用户、理解流程，并把问题翻译成 Agent 能够完成的任务。
2. 上下文：Agent 不是凭空工作的，它需要数据、记忆、权限和关系。只有创业者和创造者可以提供 Agent 所需的上下文。
3. 行动的最后一公里：模型提供推理能力，但是如何让这种推理在某一具体场景里面，可靠地转化成行动，仍然存在着大量的机会。因为完成事情意味着 Agent 需要和大量已经存在的系统发生关系，可能要调用软件、控制硬件、联系其他人，或者在多个步骤中持续工作，进入物理世界。
4. 信任和责任：Agent 可能没办法替你担责任。当 Agent 开始处理财务或者医疗信息时，谁是这个 Agent 的背后责任人？用户为什么愿意授权给他？这需要很强的产品设计、流程设计、行业知识，以及治理机制的改变。
5. 人与人之间的关系：未来最好的产品，可能不是最聪明的那个，但肯定是最懂某一类人群的那个。基础模型可以服务几亿人，但是一个创业公司，一个创业团队，只要服务好自己那 1000 个或者 1 万个用户，那一万个用户就可以了。

🔹 八、AI 时代，我们应该学什么

前面我们分析了应用层的机会。本节中我们来看看，在技术被平台内化的未来，个人该如何发展。

未来属于“会问问题的人”。现在大家常说最重要的一点是解决问题能力，但未来发现问题能力、定义问题能力，可能比解决问题能力更重要。因为 Agent 可以帮你自己解决这个问题了。

以下是几个值得培养的核心能力：

- 发现问题能力：未来属于会发现问题、定义问题的人。
- 情商与团队合作：如何和团队一起工作，如何管理团队，如何让所有人相信你自己的想法，如何把产品卖出去。这些能力可能比技术能力更重要。
- 个人品牌（Superstar）：在经济学上有一个观点叫做“巨星效应”。当你成为某一个领域的超级巨星，所有人都会觉得你说的话是对的，包括你做的产品是对的。非计算机专业的同学，可以通过做社群的方式把自己变成 Superstar，也可以通过研究某一个领域的方式，把自己成为那个领域的巨星，或者通过做小红书、TikTok，让自己成为知名度比较高的 KOL。

🔹 九、非科班学生需要掌握基础编程知识吗

刚才我们讲了未来重要的能力。本节中我们来看看，非计算机专业的同学该如何入门。

我们的观点是：基础的编程逻辑需要了解，但不一定要精通编程语言。

你需要理解：
- AI 它是如何进行变换的，Transformer 到底是什么东西
- 大语言模型是什么东西，它的逻辑是什么
- 如何在 AI 之上做一些应用
- 基础的比如知道什么是 GitHub，知道什么是代码仓库

但是，再深一层次的，关于如何编写编程这件事情，你的编程语言是否要了解清楚？我们认为不必要，因为 AI 都可以去帮你写编程语言的事情。基础的逻辑你得知道，它的底层逻辑比学习一个语言更重要。

核心逻辑可以简化为下面的代码块：

```text
理解底层逻辑 > 精通编程语言
AI 辅助编写代码 = 降低语法门槛
```

🔹 十、关于 AI 创作、版权与人类创造力

前面我们讲了非科班同学的入门建议。本节中我们来看看，AI 时代人类的创造力还有什么价值。

AI 能够做的东西，包括很多公司在处理训练数据时的一些争议。比如，有些 AI 公司把过去出版的书籍通过扫描的方式存入公司，然后销毁纸质书，包括一些孤本。为什么这件事情不合理？因为 AI 现在训练的数据取决于过去的数据，这些数据来自互联网上的公开资料，或者过去喂给 AI 的代码。但是 AI 不能推测未来，不能预测未来，未来的数据它是没有的。人类的想象力是无限的，可以突破 AI 的信息边界。

另外，很多古本、古籍或者边边角角的书，其实也没有被 AI 记录，所以 AI 也不能给你回答相关的内容。这就是为什么有些 AI 公司在做这件事情的时候，会被很多人批评。

我们认为有两个点非常重要。第一，虽然 AI 很强大，但是人类的创造力是更无限的。这就是为什么 AI 公司还是不断在给自己的 AI 喂数据，如果 AI 功能已经很强大了，它就不需要接着去喂一些孤本和人类的思考，但依旧存在，说明人类的创造力比 AI 还要强。

第二，从模型的底层逻辑和数学逻辑来看，AI 用的是过去的数据去推导未来，去预测未来的某些特征。它不像人类，人类有一个从无到有、无中生有的能力。AI 没有无中生有的能力，AI 所有的能力都是基于过去的数据去推导出来的。所以，人类的创造力、想象力、无中生有能力，是你不被 AI 替代的根本原因和逻辑。

🔹 十一、比赛中的合规风险与展示边界

刚才我们讨论了 AI 创作与人类创造力。本节中我们来看看，参加学科竞赛或创新创业竞赛时，应该如何看待合规风险。

合规风险，你可能没有办法在很短时间内去考虑到，你在创造的过程中，可能也没有考虑过合规风险这件事情。但是很多成长中的企业，很多公司，在一开始的时候，并没有考虑到合规风险。它当成长到一定地步的时候，才会去考虑合规风险，到那个时候，它的能力边界和资金量，已经足以支撑它去完善自己的合规风险了。

如果你开始因为一个合规的问题或者一些风险元素，就不敢迈出第一步，那么很多传奇的创业公司，也不会成长出来。所以在竞赛中，你可以先展示核心的创造力或者功能，合规问题可以在项目成长后逐步完善。

🔹 十二、未来人类还需要学习技能吗

前面我们讲了比赛中的合规问题。本节中我们来看看，在 AI 快速发展的背景下，人类到底还要不要学习技能。

我们认为都有。AI 的技能你是学不完的，就像我们的应用场景，人类应用产品的场景都是千奇百怪的，你很难让 AI 全部的吸收和判断。判断能力也是非常重要的一个能力。

举个例子，陶哲轩是非常传奇的数学家，他最近在证明数学公式和定理的时候，也在用 AI 辅助。他把这个场景、这个逻辑叫做 Link Process。也就是说，未来的数学证明，不一定是数学家自己去想，可以是 AI 去思考、AI 去创作、AI 去证明。数学家最后需要做的，就是在最后的阶段去做验证。这说明未来在各个行业，可能都会出现 AI 先生成，人类最后判断的模式。

所以，未来十几年或者 20 年之内，人类还是得学习，还是得去了解清楚你所在行业到底有什么样的痛点，有什么样的技能，有什么样的知识。但在 20 年、30 年之后，如果 AI 真的发展到一定程度，那可能就不需要人类的介入了，人真的就可以躺平，所有事情都可以由 AI 去操作。

🔹 十三、如何提出真正被社会需要的问题

刚才我们讨论了未来人类的学习方向。本节中我们来看看，如何从“学生思维”转变为提出真正被社会需要的问题。

很多同学会想到一些偏向于“无病呻吟”的问题，不知道如何抓住社会真正需要的问题。其实，当你作为一个读者、一个用户去提出问题的时候，你会发现这个问题解决的方式和方法，就不应该是程序员想的那一套。所有的问题都应该从用户本身去出发，这才是最重要的。

未来提出问题的人，他肯定不是程序员。很多产品不适配你，或者用户体验不好，是因为很多问题是产品经理或者程序员自己拍脑袋决定的。真正在使用过程中，你会觉得这件事情非常不符合逻辑。

以下是提出问题的几个建议：

- 不要觉得自己的问题是学生思维，也许你的问题只是还没有找到合适的买家。
- 利用 AI 的方式，你总有机会寻求到自己的客户，这个客户可能在世界上的任何一个角落。
- 你解决的不是和你生活非常不相关的一群人的一件事一个痛点，而是说这个痛点本身就对你来讲存在，你解决是自己个人的事情。

🔹 十四、AI+X 还是 X+AI

前面我们讲了如何提出真正的问题。本节中我们来看看，AI 和行业 X 的关系应该如何理解。

不应该简单地理解为 AI 加 X，或者 X 加 AI。未来的逻辑是：AI 可以帮你解决 90% 的事情，你需要做的那 10%，很有可能就是想法，有这么一个想法就可以了。然后有了这个想法，你不要担心这个产品卖不出去，因为世界上总有和你品味相同的人，他愿意购买你的想法。

🔹 十五、什么样的应用场景不容易被大模型替代

刚才我们讨论了 AI 和行业的关系。本节中我们来看看，什么样的创业方向更有未来。

任何有逻辑的东西，都容易被大模型替代。任何可以用代码实现的场景，在目前这个阶段，都很难不被大模型取代。因为逻辑性越强，越容易被大模型替代。

什么样的东西不容易被大模型替代？就是不存在逻辑的东西。比如说泡菜的发酵，比如说做饭，为什么有一些做饭大师，所谓的寿司仙人，为什么这些东西很难被大模型取代？是因为这些事情很难有逻辑，说不清道不明，中间这个东西没有办法被大模型量化。任何容易被量化的场景，未来都有可能会被大模型替代。但是人类的生活场景，人类的应用场景，有太多不能被工程化量化的东西。

在 AI 时代，用了 AI 这个大模型的能力，它可以被具体具象化、具体化、流程化、工程化。这才是未来创业的一个点，而不是说已经把过去的古法编程完全可以运行的一个东西。真正未来的应用场景，就是你身边那些事儿，你身边那些没有办法被代码实现的，或者太麻烦被代码实现的一些东西。这些应用场景是有价值的，也是有发展空间的。
