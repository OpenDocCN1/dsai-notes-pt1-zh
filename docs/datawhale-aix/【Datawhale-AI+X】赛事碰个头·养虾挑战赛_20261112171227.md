

# 🦐 Datawhale AI+X：00：养虾挑战赛 Skill 设计进阶指南

## 课程概述

在本节教程中，我们将学习如何为 Datawhale AI+X 养虾挑战赛设计高质量的 Skill。本次内容源自一次直播分享，主持人是活动学员陈某，课程作者是王一鸣老师。当前已有超过 600 名学员分布在三个社群中，共同参与这项比赛。

本教程将围绕三个核心话题展开。第一个话题是，Skill 能运行是否就意味着设计完成。第二个话题是，Skill 编写是否越详细越好。第三个话题是，使用 Skill 是否就等同于高效。我们将逐一拆解这些问题，并结合讲师的实战经验，帮助你避免常见的设计误区。

## 🦐 Datawhale AI+X：01：Skill 可用性与安全性评估

上一节我们介绍了课程的整体概述和三个讨论话题。本节中我们来看看第一个话题：Skill 能用就够了吗？

很多同学写完 Skill 后，发现代码可以跑通，就认为任务已经完成，可以直接提交。但实际上，能够运行只是基础状态，并不代表该 Skill 对你来说是真正可用的。你需要思考，你的 Skill 在市场上是否已有同类产品，对方的运行速度是否比你更快。仅仅能在 Scale 平台上运行，不能说明你的 Skill 就是高效或优秀的。

评估一个 Skill 的好坏，不能只看能否跑通，还需要关注以下几个维度。

- 运行速度与 Token 消耗。ScaleKill 的本质是用来解决问题的。如果运行特别慢，或者消耗大量 Token，就不是一个好的 Skill。
- 安全性。无论是龙虾终端还是其他任何终端，使用 Skill 都存在一定风险。龙虾的安全等级本身较低，控制范围大，不稳定的 Skill 可能会带来灾难性后果。
- 敏感信息处理。当你使用 API Key 或需要配置环境变量时，必须检查这些信息是否以明码形式存储，或者是否需要上传到某些网站。

以下是关于安全性的具体检查清单。

- 检查下载的 Skill 是否安全。社区下载的 Skill 不一定可靠，建议使用安全检查类 Skill 进行扫描。
- 避免硬编码 API Key。编写资料时，不要把 API Key 直接写死在代码中，最好将其管理到本地环境变量。
- 防止危险操作。Skill 执行时可能会进行一些危险操作，你需要注意防止对电脑造成损害。
- 多步执行前的防护。如果涉及执行步骤较多或安全性问题的场景，应提前做好防护和测试。




## 🦐 Datawhale AI+X：02：渐进式披露与结构优化

上一节我们介绍了 Skill 的可用性与安全性评估方法。本节中我们来看看如何优化 Skill 的内部结构。

Skill 写完之后，还需要关注结构优化。如果结构设计不合理，会导致执行任务时消耗过多 Token，并且在第二次迭代时变得非常麻烦。此外，如果 Skill 文档编写不符合规范，使用该 Skill 的大模型可能会走很多弯路，例如在执行日志中不断打转圈，这些都是设计不合理的表现。


有些同学认为，把 Skill 写得越详细越好就可以了。但实际上，编写 Skill 有一定规则，其中最重要的是渐进式披露原则。公式如下：


```
Skill 结构 = 必须加载内容 + 按需加载内容 + 参考文档
```

具体说明如下。

- 必须加载内容。每次执行 Skill 时都需要默认加载的部分，例如前置提示信息。如果这部分写得粗糙，Skill 被触发的概率会很低。
- 按需加载内容。正文部分只在用到时才加载。例如生成 PPT 时，才去搜索并加载生成 PPT 的具体方法，读取 reading content、creating 等相关段落。
- 参考文档。大量案例和详细说明文档应放入 reference 目录，例如详细的 PPT 设计说明。这样可以避免主文档过长，降低扫描时的 Token 消耗。


举一个具体的例子。PPT generate Skill 即使内容非常丰富，主文档也只有 249 行，并不冗长。再看另一个 DUCDCX 的 Word 类文档 Skill，虽然文档也不算长，但其中的脚本等内容都按需存放。建议你采用这种渐进式结构编写，而不是将所有内容堆砌在一个 MD 文档里。

另外，Description 字段的精确描述也非常重要。当你有多个相似的 Skill 时，例如两个都是 PPT 生成 Skill，一个更适合生成报告，另一个更适合生成活跃内容，你需要在描述中明确区分。否则 AI 可能无法正确选择，每次都调用另一个不符合你预期的 Skill。公式如下：

```
Skill 优先级 = 描述精确度 × 场景匹配度
```

## 🦐 Datawhale AI+X：03：Token 效率与工作流优化

上一节我们介绍了渐进式披露与结构优化方法。本节中我们来看看 Token 效率与工作流优化。

使用 Skill 不等于高效。有些官方 Skill 并不适合国内本土化使用，例如依赖谷歌全家桶的 Skill，国内用户使用起来非常麻烦。还有些 Skill 是针对 Mac 或 Linux 系统编写的，放到 Windows 上可能无法运行。此外，安全性问题也可能让某些 Skill 对你来说变成“炸弹”。

因此，你需要养成检查 Skill 的习惯。在刚拿到一个 Skill 时，检查其使用的工具、适用场景、版本问题以及系统兼容性。如果多个 Skill 共存，还需要考虑修改配置文件等设计和判断问题。

Skill 本质上是一个 Token 杀手。即使你的 Skill 写得再好，每次只执行部分命令，它仍然会携带上下文信息，不是一个最精简的可执行单元。Agent 应用与 Workflow 应用的区别在于，智能化应用虽然有智能，但代价是不停反思、不停调整、不停执行，这会导致 Token 浪费。公式如下：

```
Token 消耗 ∝ 上下文长度 × 调用次数 × 反思次数
```

如果你发现 Skill 总是不够用，但又必须使用 Skill，可以考虑引入经典工具来搭建工作流。以下是推荐的工具。

- N8N。可用于搭建可视化工作流，有效减少 Token 使用，并帮助你更好地理解业务逻辑。
- Dify。同样适合构建工作流，降低对单一 Skill 的依赖。



编写 Skill 时，也要注意模块划分。例如某个模块内容过长，每次调用都要读取整个模块，就会浪费大量 Token。如果该模块再写得更详细，包含血化验报告分析、X 光、核磁等大量内容，全部读一遍 Token 就顶不住了。因此，优化方向之一就是合理拆分模块，避免全量读取。

## 🦐 Datawhale AI+X：04：Skill 融合与触发管理

上一节我们介绍了 Token 效率与工作流优化。本节中我们来看看 Skill 的融合与触发管理。

如果你觉得自己写的 Skill 不好，可以先使用，同时寻找优秀的 Skill 学习。每次使用时，记得检查 Skill。如果不会检查，可以直接打开对话工具，提出几个问题，或者使用苏格拉底反问法让 AI 来问你，从而在使用过程中积累经验。


即使完成相同任务，也可以用不同的 Skill 实现思路。例如生成 PPT，一种是先用代码生成再用脚本转成 PPT，另一种是直接生成 HTML 然后转成 PDF 当作 PPT。多看多比较，就能掌握不同的设计方式。


Skill 融合是指将多个简单 Skill 的功能合并到一个 Skill 中。公式如下：


```
融合 Skill = Skill A 功能 + Skill B 功能 + Skill C 功能
```


例如写论文时，你可以把摘要生成、文献查阅、论文总结合并为一个“论文处理与写作” Skill，每次只需调用一个 Skill 即可，达到提效目的。

另外，关于 Skill 的触发关键字。如果某个 Skill 触发过于频繁，你可以编写不触发该 Skill 的条件，即反向定义触发逻辑。触发管理依然使用前置配置文件。这样可以让 Skill 的调用更加精准。

## 🦐 Datawhale AI+X：05：学员实战案例分享

上一节我们介绍了 Skill 融合与触发管理。本节中我们来看看几位学员的实战分享，了解实际项目是如何落地的。

### 5.1 麦当劳点餐 Skill

李夏老师，一名高二学生，分享了基于麦当劳官方 MCP 开发的点餐 Skill。他发现直接调用 MCP 不方便且占用大量上下文，因此将其封装成了 Skill。

该 Skill 内置了 19 个工具，不仅可以查询餐厅和菜单、下单，还可以兑换积分、领取优惠券。演示过程中，Skill 能够自动调用正确方法查询菜单，即使调用失败也会尝试正确方法重新调用。下单后会返回订单号、时间、取餐方式、门店信息、商品清单、费用明细和支付链接。支付仍需在小程序中手动完成。

关于最优决策，官方 MCP 提供了挑选最便宜价格的工具。例如某商品原价 122 元，开通金卡后可享受减免，实付金额由系统自动计算。Token 使用量约为 300 多个，属于可接受范围。

### 5.2 论文参考文献 Skill

艾徽同学分享了论文参考文献处理 Skill。输入 PDF 或 DOI 格式，输出符合课题组要求的标准 BibTeX 格式。

传统做法需要从 Google 学术或 Archive 复制引用信息，一篇文章可能有六七十个参考文献，复制和核对非常耗时且繁琐，且容易出现格式不匹配的问题。更严重的是，如果使用 AI 生成虚假参考文献链接，可能会被会议拒稿，甚至被封禁五年。该 Skill 支持联网搜索，可自动生成规范格式，大幅减少检查和生成的时间与精力，避免学术造假风险。

### 5.3 猫娘互动 Skill

闫一同学来自中科大，分享了以猫娘口吻进行互动的 Skill。其流程包括记忆预加载、分身编排器路由、Prompt 加载、工具调用拦截与翻译、评价记录保存。

当用户提问时，大模型先经过分身编排器，加载相应的生活技巧或跨领域 Prompt。每个 Prompt 约 1400 多个字。Skill 会拦截工具调用反馈，将其翻译成猫娘语气回复。用户评价会通过向量数据库或知识图谱保存，使 Skill 能够自我进化。目前该 Skill 已有约 4000 次下载人次，并提供 10K 和 30K 版本的 QA 数据集，数据也可用于模型微调。



### 5.4 公式识别与家居监测 Skill

罗米奥同学，大三本科生，分享了两个 Skill。第一个针对论文公式识别，可将公式转化为 LaTeX 代码，解释变量物理意义，推导求解过程，并生成结构化论文摘要。第二个是生物适应性家居系统，用于实时监测家庭成员生命体征并自动调节室内环境参数。

### 5.5 职业替代率评估 Skill

张清亮老师，产品经理，分享了职业替代率评估 Skill。基于美国劳工统计局数据和中国国家职业分类大典，分析了 340 个职业，覆盖 1.45 亿就业人数。

AI 暴露度评估范围为 1 到 9 分，分值越高，越容易被替代。评估维度包括重复性规则化程度、数据处理占比、人际情感需求、创造力及决策复杂度、物理操作、法律约束等。公式如下：

```
替代风险分值 = f(重复性, 数据占比, 人际需求, 创造力, 决策复杂度, 物理操作, 法律约束)
```

分析得出三大规律：知识密集度决定风险，教育要求与风险正相关，薪资与风险弱正相关。建议大学生优先选择医疗护理、技能维修、创意、线上服务等领域，谨慎选择行政基础、常规销售、简单管理等容易被 AI 替代的岗位。

## 🦐 Datawhale AI+X：06：总结与建议

上一节我们介绍了多个学员的实战案例。本节中我们来对本教程进行总结。

在本教程中，我们一起学习了以下内容：

- Skill 能运行并不代表设计完成，还需要关注运行速度、Token 消耗和安全性。
- 编写 Skill 应遵循渐进式披露原则，将内容分为必须加载、按需加载和参考文档三部分，并精确描述 Description 字段。
- 使用 Skill 不等于高效，Skill 是 Token 消耗大户，必要时应引入 N8N 或 Dify 等工作流工具。
- Skill 可以融合多个功能，并通过反向定义不触发条件来管理触发逻辑。
- 实际案例表明，Skill 可以应用于点餐、论文写作、角色扮演、公式识别、职业评估等多种场景。
