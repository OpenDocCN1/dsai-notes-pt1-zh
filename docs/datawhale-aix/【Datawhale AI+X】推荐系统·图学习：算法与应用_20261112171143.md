

# AI推荐系统与智能体前沿教程：1：自我改进推荐系统框架 🚀

在本节课中，我们将学习如何让推荐模型利用自身的推荐能力，构建一个自我改进的闭环系统。传统的推荐系统在发展过程中，通常会遇到两个比较典型的困境。第一种情况是，当我们无法获得更强的模型时，新的训练数据应该从哪里获取。第二种情况是通过启发式方式来增强已有数据，比如对数据进行掩码或者交换顺序。通过这种方式，我们确实可以得到一些新的数据。但是，启发式方式一方面可能会引入噪声，另一方面带来的问题是，它实际上只是对模型已用模式的组合，并没有引入任何新的真实有效信息。

这两种路径都有它们固有的问题，并没有办法从根本上去解决问题。那么，怎么去获得真实有用的偏好信号，仍然是一个悬而未决的问题。这个困境促使我们从一个新的角度来思考信号的来源。我们注意到一个事实，就是推荐模型其实本身是具备推荐能力的。在以往来说，这种推荐能力只是进行很多次推理，然后给模型去推荐他可能喜欢的物品。但是，这种能力并没有想办法把它反哺到推荐模型本身。

那么，我们就想了一个非常直观的想法，就是怎么利用推荐系统自身的这种能力，来构建一个自我改进的框架。具体做法是，先让这个模型凭借自身的能力去构造一个更好的数据，然后再利用这些数据去训练一个更好的模型。那么，这样一个模型是否就可以反补回数据？通过这种方式，我们来构建这样一个闭环的系统，让模型进行自我改进。

想要实现这样一个自我改进，可能目标就有两个。第一个目标，就是怎么去利用模型自身的这样一个能力，让他去生成真正有价值的数据。第二个目标，就是防止在这个过程中，模型它本身由于自身的能力的一个限制，让它自身错误在这样一个闭环系统里被反复的确认和不断的累积。所以，这两点也是我们后续设计框架和方法着重考虑的两个问题。

我们在这篇论文里，将上述的这样一个设想给他进行了一个实例化的设计。就像这个图展示的那样，它实际上是一个非常简单的递归的闭环。在每一轮的系统里，每一轮的迭代里模型去构建一部分生成的数据。然后，我们把这种生成数据来做一个过滤。这个过滤就是所谓的保证入锅滤。他实际上是想保留下那些正确的、可信的用户序列，而把那些错误的用户序列给他丢弃掉。那么，我们利用这个构造好的新的数据，再去训练一个更浅的模型。这是单次闭环想做到的事情。

如果能够把这种单次闭环无限次做起来，我们理论上可以获得更强的模型。然后，我们设计两个模块，也是对应着上一页讲了两个目标，以及怎么去生成，以及怎么去控制。分别来设计了。我们接下来是分别对这两个模块来进行介绍。

第一个模块是有些探索。它实际上的动机也非常简单，就是说，如果我们让模型去自主的去从整个物品实里去生成，那么可能这个难度非常大。因为那个模型自询能力有限制。所以，我们给他构造一个候选样本池，它实际上是分为有界的一个探索，以及怎么去把我们用户已经展示过的偏好给他利用好。第二个的话就是去全局的一个探索，也及于我们怎么去合理的把用户他暂时没有展现出来这种交互，给他加入到我们的物品池里。那么，具体方式的话也非常简单，也就是我们随机采样。以下是候选采样的具体策略：
