Datawhale AI+X 黑客松全攻略：01：黑客松定义与起源 🎯

上一节我们简单介绍了本课程将要学习的内容，以及三位嘉宾的不同背景。本节中我们先来聊聊黑客松到底是什么，它的名字是怎么来的，以及它和普通比赛有什么不同。

黑客松这个词是一个音译，它由黑客（Hack）和马拉松（Marathon）两个词拼合而成，可以用下面的公式来理解：

黑客松 = 黑客 + 马拉松

有人也把它称为编程马拉松，听起来好像一定要会写代码才能参加，但实际上并不是这样的。黑客松更像是一个现实中的即客游戏，或者是一个快速把点子变成可见成品的场合。参赛者通常在有限的时间内，围绕一个命题或者一个痛点，快速搭建一个可以运行的原型，最后通过演示、PPT、视频或网页等形式进行展示。

黑客松主要分为两种形式。一种是线下黑客松，参赛者需要带着电脑来到现场，在规定的时间内完成开发，现场气氛比较紧张，适合当面交流和组队。另一种是线上黑客松，在固定的时间段内报名和提交，评审和优化都在网络上进行，适合无法到场的同学。

从产品开发的角度来看，你可以把黑客松类比为软件工程里的测试环境，而正式上线的商业产品则类似于生产环境。黑客松给了你一个相对安全、封闭且容错率较高的空间，让你可以大胆尝试新想法，练习产品思维，锻炼对AI工具的驾驭能力，同时也能提升综合素质。对于还没有进入社会，或者想要提升自己的大学生来说，它是一个非常重要的试验场。

Datawhale AI+X 黑客松全攻略：02：是否需要编程基础 💻

在了解了黑客松的基本定义之后，很多同学会担心自己不会编程，是不是就没有资格参加。本节我们来探讨参加黑客松是否需要编程能力，以及非技术背景的同学该如何应对。

以下是关于编程能力与黑客松参与关系的几点说明：

- 黑客松不强制要求所有成员都会写代码。现在有大量的AI编程工具，例如Cursor和CodeEx，可以帮助非技术同学通过自然语言描述需求来生成前端和后端代码，实现零代码或低代码开发。
- 孙彤同学是计算机专业本科生，他基本以单人形式参加黑客松，主要依靠AI辅助编程完成作品。叶艳同学是生物与医药专业的工程博士，最初连编辑器都没有下载，现场才临时借账号开始开发，也顺利完成了参赛。
- 王真同学作为产品经理，从产品和商业视角帮助选手梳理思路，也证明了非技术角色在黑客松中同样有价值。
- 有一次活动中，CodeEx因为算力不足出现了瘫痪，当晚很多熬夜赶项目的同学发现无法继续编程，只能回去睡觉。这个现象说明，越来越多的同学依赖AI来辅助编程，编程能力不再是参与黑客松的绝对门槛。

简单来说，黑客松更看重你发现问题和解决问题的能力，而不是你是否能熟练写出每一行代码。如果你有想法，愿意动手尝试，完全可以参加。

Datawhale AI+X 黑客松全攻略：03：组队与分工指南 👥

上一节我们讨论了编程能力并不是参加黑客松的必要条件。本节我们来聊聊，如果你决定组队参加，应该如何找到靠谱的队友，以及一个典型的团队应该如何分工。

以下是组队与分工的建议：

- 现场组队通常会在比赛微信群里进行。你可以先简单介绍自己，说明感兴趣的方向，以及之前掌握的相关技能，或者展示之前做过的小作品，比如简单的界面、NFC小程序等，吸引志同道合的队友。
- 一个比较常见且合理的配置是三人团队。理想情况下，团队中最好有一位既懂产品又懂技术的负责人，避免大家各自为战；另外可以找一位懂技术或硬件的大佬，负责具体的实现；再找一位懂前端或用户体验的同学，负责界面设计和用户心理分析。
- 队友的性格特质也很重要。在创意发散的阶段，会有很多想法多、行动快的同学，但他们可能难以长时间专注在一件事情上。对于短时间内需要出结果的黑客松来说，更适合找那些稳重、能保证稳定产出的队友。
- 团队中需要有人擅长对外展示，能把想法清晰地讲出来，担任PPT路演的主讲人；同时也需要有人负责出主意，有人负责统筹安排，确保各项工作有序进行。
- 关于是否可以完全依赖AI代替队友，作者的观点是，人多力量大。三个人每天24小时，理论上拥有72小时的开发时间。虽然团队内部会有沟通成本，但作品的完成度和学到的东西通常会更多。对于性格偏内向的同学，也建议尝试突破自己，寻找伙伴一起参赛。

Datawhale AI+X 黑客松全攻略：04：点子来源与MVP 💡

有了团队之后，接下来最关键的问题是做什么。本节我们来谈谈点子是怎么挖掘出来的，以及如何确定一个适合黑客松的最小可行产品，也就是MVP。

以下是点子来源和MVP的相关方法：

- 从自身痛点出发。孙彤同学在写基金论文时，发现文献检索、管理和阅读之间缺乏一个一体化的工具，于是做了一个全流程的论文写作管理和推荐平台。王真同学的家人体检后看不懂报告，医生讲解又太快，于是她做了一个体检报告AI解读工具。叶艳同学结合医学背景和医院调研，做了一个中医智能导诊和智慧药房方案。
- 从现场调研中发现需求。叶艳同学曾进入县城医院走访，发现基层医院在分诊、药房管理和医生诊疗辅助方面存在实际问题，这些都可以成为切入点。
- 从社交平台和竞品分析中验证。你可以在小红书、公众号或知乎上搜索，看是否有其他人遇到过同样的问题，查看差评和评论区，判断你的点子是否有真实需求，是否过于狭窄。
- 验证一个点子是否可行，可以参考太阳下面没有新鲜事这个观点。基本上你想到的点子，或多或少已经有某种形式的解决方案，你可以先调研竞品，看看他们是如何解决的，以及用户对现有方案的不满在哪里。

关于MVP，可以用下面的公式来辅助理解：

MVP = 核心功能 + 最小输入输出 + 基础模型提示词

MVP不需要完美，不需要把所有功能都做出来。你可以把它想象成做汉堡，如果时间和材料有限，你可以先只做汉堡肉饼，虽然不完整，但已经是一道可以独立尝试的菜品，用户能够体验到核心价值。黑客松的时间非常紧张，通常只有两到三天，所以必须学会取舍，把那些暂时无法实现的功能留到后续迭代中，先确保核心流程能跑通。

Datawhale AI+X 黑客松全攻略：05：AI开发工具推荐 🛠️

确定了点子之后，接下来就是动手开发。本节我们来看看，不同水平的同学可以使用哪些AI工具来提高效率。

以下是推荐的AI开发工具：

- 对于编程基础较好的同学，可以使用Cursor、CodeEx、Trae，以及VS Code配合各种AI插件。模型方面，可以根据条件选择GPT、GLM、Minimax或DeepSeek等。CodeEx在代码生成、PPT制作甚至视频辅助方面表现不错，Cursor在代码补全和项目结构生成上也很强大。
- 对于完全不会代码的初学者，建议平时就开始储备工具，不要等到报名了才临时学习。国产方面可以尝试腾讯的Workbody，以及谷歌的AI Lab。Google AI Lab特别小白友好，它可以在你输入需求时，实时预测和补充你接下来想说的话，帮你把模糊的想法填充成专业的产品需求描述。
- 使用示例，你可以在对话框中输入“我想做一个管理我日常喝水量的小工具”，然后稍作停顿，AI会继续帮你把需求完善清楚，生成比较完整的设计思路。
- 大部分国产工具只需要绑定信用卡，平台通常会赠送一定的免费额度，足够你完成多个练习作品。即使不需要国外上网或支付能力，也可以用国产替代方案进行产品练习。

如果你使用VS Code，可以尝试以下方式嵌入AI插件：

```json
{
  "recommendations": [
    "ms-vscode.vscode-code-ex",
    "cursor.cursor",
    "github.copilot"
  ]
}
```

这个配置只是一个示例，实际安装时可以根据你的习惯选择合适的插件。

Datawhale AI+X 黑客松全攻略：06：路演与演示技巧 🎤

作品开发完成后，接下来就是如何把它展示给评委和观众。本节我们来分享路演和PPT制作的实用技巧。

以下是路演时的关键建议：

- 开场一定要有钩子。用一个贴近实际、脚踏实地的痛点或问题开始，把评委的注意力勾住，让大家觉得这个问题是真实存在的。
- 讲清楚产品的起源，解释你为什么想到这个点子，这个故事要具体且真实。
- 功能演示建议使用视频、动图或直观的截图，而不是只放一张静态图片。否则评委可能会质疑你的作品只是一个PPT、一个Demo，甚至只是空话。
- 附上竞品分析，说明你解决的问题、你的解决方案、以及与现有方案相比的优势。这既是对产品的自信展示，也证明你做过市场调研。
- 叶艳同学的创业路演框架包括：项目痛点、针对痛点的具体方案、创新点、商业模式（如何赚钱或可持续发展）、团队介绍、技术细节与架构，以及最后配上一分钟的展示视频。

Datawhale AI+X 黑客松全攻略：07：评委视角与作品打磨 🏆

了解了路演技巧之后，我们换个角度思考：如果你是评委，你希望在作品里看到什么？本节我们来站在评委的视角，聊聊如何让自己的作品更有竞争力。

以下是评委视角下的建议：

- 提前了解本次黑客松的评分维度，这些通常在赛前是公开的。你可以在团队内部按照评分标准自我评估，看看项目还缺什么，类似于高考后估分对标准答案。
- 准备测试用例，也就是Test Case。有的团队会在提交文档里贴心地附上可以直接测试的材料，比如示例输入文本、可上传的文件，或者具体的操作步骤。评委不需要自己费劲脑汁去构造不靠谱的题目，可以直接用你提供的材料体验产品，这会让评委觉得非常贴心。
- 把评委当作你的第一个用户。求职时简历和作品集也要考虑HR的视角，黑客松作品也一样，要想方设法让评委快速感受到产品的价值和美感。
- 高分作品通常具有以下特质：第一，拥有完整的工作流，从问题产生到最终结果形成闭环；第二，解决的问题不是泛泛而谈的，而是带有特定条件或特殊人群的；第三，可以用新视角解决旧问题，比如用游戏视角解释高中生物题。

Datawhale AI+X 黑客松全攻略：08：从想法到成品的工作流 🔄

在前面几节中，我们分别讨论了黑客松的定义、组队、点子挖掘、工具选择、路演和评委视角。本节我们将这些内容串联起来，梳理从想法到成品的完整工作流。

以下是完整的工作流步骤：

- 第一步，考虑idea的可行性。确认是否存在真正的需求，以及实现的可操作性。
- 第二步，决定实现形式。是纯软件产品，还是软硬结合。如果是纯软件，开始分工，谁负责前端，谁负责后端，谁负责哪个功能；如果是软硬结合，则需要两条线并行开发。
- 第三步，制作第一版产品。完成后，团队内部先自己使用，发现问题，进行优化和调整，这就像测试开发岗位的作用。
- 第四步，迭代与呈现。部分同学继续迭代功能，另一部分同学开始制作PPT、PRD或Demo等呈现材料。
- 第五步，个人工作流定制。每个人的习惯不同，有的人喜欢把文书工作分散到等待AI输出的空闲时间里完成，建议你在参加过一次黑客松后，根据自己的习惯私人定制一套流程。
- 产品经理视角下的敏捷开发建议：先确定人员分工，避免大家重复做同一件事情；达成对产品价值和目标用户的共识；第一个版本可以比较简陋，但核心功能、输入输出数据、所用模型和基础提示词必须确定；经过几轮讨论和修正，产品方向会越来越垂直、越来越好。

最后，无论是否有完美的工作流，参加黑客松更像是在一个公司里实习，面对不同的人和不同的想法，学会协调、达成一致，把一个抽象的点子推向领奖台，这个过程本身就非常过瘾，也非常锻炼人。
