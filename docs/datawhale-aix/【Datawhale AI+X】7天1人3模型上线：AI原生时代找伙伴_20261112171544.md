## 3. 后端架构设计与安全防护

以下是后端架构设计和安全防护的主要内容。

![](img/425964b5531e122f23e422e2c16b6fcd_26.png)

![](img/425964b5531e122f23e422e2c16b6fcd_27.png)

![](img/425964b5531e122f23e422e2c16b6fcd_28.png)

首先需要设计整个后端架构，重点考虑安全和隐私问题。这个项目不是按普通标准写的，而是按照高安全性和工程化规范编写的，因此涉及很多安全审计内容，比如XSS攻击防护和权限管理。开发过程中遇到很多坑和问题，比如迁移时路径写错导致无法保存项目，但都在很短时间内修复了。快速定位问题需要对后端有基本了解。更新记录可以在网页上查看，也欢迎大家加入社区反馈。

![](img/425964b5531e122f23e422e2c16b6fcd_29.png)

![](img/425964b5531e122f23e422e2c16b6fcd_30.png)

以下是安全防护的常见措施：
- 输入过滤：不允许脚本输入
- 文件过滤：不允许病毒文件上传，只支持特定格式
- 图片治理：违规图片上传后立即失效
- 文本治理：违规文本直接检测，不发送或仅自己可见
- 限流中间件：防止平台被刷，违规IP会被封禁
- 并发处理：避免人多时数据混乱或出错

代码：
```
安全审计 = XSS防护 + 权限管理 + 限流 + 内容治理
```

## 4. 前端技术栈与UI设计

![](img/425964b5531e122f23e422e2c16b6fcd_45.png)

以下是前端界面设计和技术栈的选择思路。

界面是用户接触产品的第一关，所以颜值很重要。注册页面和个人卡片分享界面都做得比较精美。主体框架使用了谷歌的A96组件库，风格是漫画涂鸦，整体简单好看。前端在半个小时内就完成了第一版最小可行产品，因为使用了现成框架，不需要重复造轮子。项目列出了第三方开源组件声明，所有使用的开源框架和库都在网站底部或开源页面说明。如果不知道有什么开源库，也可以让AI帮忙找现成方案，而不是自己从零实现。

## 5. 部署方案与服务器选择

以下是部署方式和服务器的选择建议。

![](img/425964b5531e122f23e422e2c16b6fcd_51.png)

如果你是纯Web开发且没有后端经验，建议直接选择全站框架，前端和后端在同一个项目里，这样部署方便，AI也更容易读懂代码。可以一键部署到Vercel或Hone等平台，不需要自己购买服务器。数据库可以使用免费版，比如Neon，基础能力已经足够，普通项目用户不多时完全够用。如果项目很大，用户超过一万人，再考虑购买服务器或付费数据库。我之前买过2核2G服务器，遇到过内存不足导致构建失败的问题，最后换成了大一点的服务器。阿里云、腾讯云的便宜服务器大概一百多元一年。

代码：
```
部署方案 = Next.js全站框架 + Vercel/Hone一键部署 + 免费数据库
```

## 6. 数据库与迁移方案

![](img/425964b5531e122f23e422e2c16b6fcd_57.png)

![](img/425964b5531e122f23e422e2c16b6fcd_58.png)

以下是数据库选择和数据迁移的实际操作。

![](img/425964b5531e122f23e422e2c16b6fcd_60.png)

全站框架是无状态的，代码上传到任何服务器都一样，只需要在服务器上新建Node环境，绑定域名就能上线。数据库可以和服务器放在一起，方便管理。数据迁移也很丝滑，可以直接把数据从旧环境过渡到自己的服务器上。对于没有数据库基础的初学者，不需要一开始就买服务器，先用免费额度熟悉流程，等用户增加后再迁移也不算太麻烦。

公式：
```
无状态应用 = 代码在任意服务器上行为一致
```

![](img/425964b5531e122f23e422e2c16b6fcd_62.png)

![](img/425964b5531e122f23e422e2c16b6fcd_64.png)

代码：
```
迁移步骤 = 上传代码库 → 新建Node环境 → 绑定域名 → 迁移数据库
```
